2. Gesamtlage

6kritische Verlust-/Notenpfade
18hohe Risiken (Daten, HIS, UX)
Client-onlykein Noten-Backend, lokale IndexedDB
44/44bestehende Noten-Regressionstests grün

ExamGrade ist fachlich weit: HIS-Re-Export, Orphans, Szenarien, Portfolio mit Korrektoren, Leistungs-PDF. Die größten Restrisiken liegen nicht in der UI-Politur, sondern in Datenverlust durch Auto-Save/Tabs, fachlich überraschender Notenrechnung (StA-Note-Skala, Mixed-Portfolio, 4,5→4,0) und Identitätsfehlern beim Import (falsche Matrikelspalte, Komma-Artefakt).

Sicherheit entspricht dem dokumentierten Modell (Zugangshürde, keine Cloud). Das ist für interne Prüfer akzeptabel, wenn klar bleibt: das Passwort im Bundle ist kein Geheimnisschutz.

4. Datenintegrität und Auto-Save

Kritisch Letzte Änderung geht beim Verlassen verloren

use-auto-save.ts bricht den 800-ms-Debounce im Cleanup ab, ohne zu flushen. Wechsel zur Prüfungsliste oder Tab-Schließen innerhalb der Debounce-Zeit verwirft die letzte Zelle.

Behebung: Bei Unmount/pagehide persistNow(projectRef.current), wenn dirty. Eine Writer-Queue, damit Debounce und 15-s-Intervall sich nicht überholen. dirtyRef nur löschen, wenn die geschriebene Revision noch aktuell ist.

Kritisch Zwei Tabs: Last-Write-Wins

Kein revision, kein BroadcastChannel. Tab A überschreibt Tab B und löscht den Draft. Listen-Export/Semester-ZIP speichert den Listenstand (ohne Draft) und markiert ihn als Sicherung – kann neuere Tab-Daten überschreiben.

Behebung: Monotone Revision vor dem Schreiben prüfen. Nach Import/Replace/Delete Broadcast → Reload. Export immer aus getExam+getDraft mergen.

Kritisch Duplikat „für Folgesemester (ohne Daten)“ behält HIS

duplicateExamProject leert hisRows, nicht hisSources. migrateExamProject baut die Masterliste inkl. Base64-Excel wieder auf. Personenbezogene Daten wandern ins Folgesemester.

Behebung: Bei clearData auch hisSources, Merges, Dismissals, questionDefs, Backup-Meilensteine leeren.

Hoch Replace-Import vs. offener Editor

Konflikt-Dialog warnt korrekt. Ein offener Tab schreibt danach per Auto-Save die lokale Version über den Import. Import ohne Match vergibt immer eine neue ID – Bookmarks und Re-Match per ID sterben.

Behebung: Vor Replace Snapshot. Nach Replace Tabs invalidieren. Ohne Konflikt Import-ID behalten.

Hoch Migration nicht idempotent

Jedes Lesen von Schema < 2 erzeugt neue Szenario-UUIDs, bis gespeichert wird. rebuildScenariosForMaxPoints vernichtet Custom-Schwellen. HIS-v3 überschreibt hisRows immer aus hisSources.

Behebung: Stabile Preset-IDs (sc-pass50 …). Custom-Schwellen als Prozent persistieren. hisRows nur ableiten, nie als zweite Wahrheit.

Hoch Backup als „frisch“ trotz fehlgeschlagenem Download

void downloadJson + sofort markProjectBackedUp. File-Picker-Abort oder Teams-Blockade gibt Exporte frei, obwohl keine Datei existiert. ZIP-Namen ohne Uhrzeit: zwei gleichnamige Prüfungen → eine Datei fehlt, beide gelten als gesichert.

Behebung: Nur nach erfolgreichem downloadBlob markieren. ZIP-Dateiname um kurze ID erweitern.

5. Notenlogik und Edge Cases

Kritisch StA-Kriterien mit Skala „Note“ durchlaufen den Punkteschlüssel

Unit aus Note 2,0 ist 0,75 → ×100 → calculateGrade(75) oft 2,3. Überall 4,0 (bestanden) kann 5,0 werden. Portfolio-Note-TLs rechnen bewusst linear 5−4·unit – StA nicht.

Behebung: Wenn alle StA-Kriterien Note-Skala: gewichtetes Notenmittel + deutsche Rundung. Mixed Grade+Punkte: TL-weise zuerst Note, nie Grade→Punkte-Schema. UI-Warnung.

Kritisch Mixed-Portfolio: TL-Mittel ≠ Gesamtnote

Eine Punkte-TL (80 % → 2,0) plus eine Note-TL (2,0) ergibt sichtbare TL-Noten 2,0 / 2,0, Gesamt aber Unit-Mittel 0,775 → oft 2,3. Im Matrix-Skript als A8 festgeschrieben.

Behebung: Gesamtnote = gewichtetes Mittel der berechneten TL-Noten. Szenario nur innerhalb der Punkte/%-TLs. Tests A8 neu spezifizieren.

Kritisch Rohmittel 4,5 wird 4,0 (bestanden)

roundToNearestGermanGrade wählt bei Gleichstand die bessere Note. Abstand 4,0–5,0 = 1,0; Mitte 4,5 → 4,0. Viele Prüfungsordnungen: ab 4,5 nicht bestanden.

Behebung: Konfigurierbare Regel (Default PO: < 4,5 → 4,0, ≥ 4,5 → 5,0). Tests 4,49 / 4,50 / 4,51.

Hoch Gewicht 0 hat drei Semantiken

Note ignoriert Gewicht 0; Missing-Zähler verlangt den Wert trotzdem; Rohpunkte behandeln 0 als Gewicht 1. Folge: Export gesperrt trotz berechneter Note – oder verfälschte Punktsumme.

Behebung: weight ≤ 0 = deaktiviert überall.

Hoch Statistik und No-Show

  • Multi-HIS: dieselbe Person zählt doppelt in Ø und Bestehensquote.
  • StA/Portfolio-No-Shows erscheinen in noShowRate nur bei importierter Antrittsliste.
  • Override 1,5 / 2,5 / 4,3 fehlt in der Notenverteilung (|Δ| < 0,05).
  • Leistungs-PDF rechnet Teilnoten aus unvollständigen Kriterien, während die Amtsnote leer bleibt.

Behebung: Kennzahlen nach Matrikel deduplizieren. Nenner der Bestehensquote beschriften. Partial-Noten im PDF nur als „vorläufig“ oder weglassen, solange finalGrade == null. Disabled-Kriterien der Gruppe auch im PDF beachten.

Mittel Weitere Kanten

  • TL ohne aktive Gruppen-Kriterien bleibt dauerhaft „unvollständig“.
  • Dozentenmodus an: Kriterienwerte werden nicht geseedet (nur einfache Teilnoten).
  • notAttended bei Personen ohne HIS ergibt Status mismatch, nicht No-Show.
  • Attendance-Import setzt faktisch immer „angetreten“ (a.attended ungenutzt).
  • Override räumt offene Moodle-Aufgaben nicht weg → Export bleibt gesperrt.

7. Abläufe und Nutzung

Der fachliche Soll-Ablauf ist im Handbuch klar. Die UI weicht an mehreren Stellen davon ab oder lässt Sperren unsichtbar.

7.1 Dead Ends

  • Dokumente sperren ohne die Validierungsliste (die steht nur unter Sicherung). Handbuch §13.4 verspricht Hinweise auf der Dokumente-Seite.
  • Manuell abgeschlossen setzt die Startkarte auf 100 %, ändert Export-Gates nicht. Zwei Zustände verwechseln: Fortschritt vs. exportbereit.
  • THE: Workflow-Schritt „Sicherung nach Import“ liegt vor den Punkten, verlangt aber bereits Punkte (importsComplete).
  • Auto-Save „Gespeichert 14:32“ wird mit JSON-Sicherung verwechselt – HIS bleibt gesperrt.

Konkrete UX-Fixes: Blockerliste + CTA auf Dokumente. Sticky „Noch 3 von 42“ in der Matrix. Übersicht/Quicklinks/Kennzahlen je Prüfungstyp. Sidebar unter md als Sheet. Prüfungstyp nach erstem Import sperren oder bestätigen. Import-Konflikt: Esc nicht still skippen. Semester-ZIP am Filter ausrichten.

7.3 Analyse für Prüfer

  • Grenzfälle, Durchfaller, Szenario-Impact und Leistungs-PDF sind stark – aber Statistik-Nenner und Multi-HIS-Duplikate entwerten Ø/Quote.
  • Szenarien bei reinen Note-TLs in der Navigation ausblenden.
  • Notenspiegel nur an einer Stelle (Dokumente), Grades mit Deep-Link.
  • Korrektoren: Diskrepanz > 0,7 Notenstufen als Hinweis (heute nur Mittel).

8. Bewertungskriterien und generative KI

Im Katalog (exam-catalog.ts) gibt es keine fachlichen StA-/Portfolio-Kriterien. Defaults:

  • StA: leere Liste; Button erzeugt „Neues Kriterium“, Skala Prozent.
  • Portfolio: TL1/TL2; Kriterienmodus startet mit einem Kriterium „Inhalt“, Punkte 0–6.

Gemessen wird ausschließlich ein Prüferurteil über das Endprodukt (eine Zahl). Prozess, Mündliches, Reproduktion und Quellenstichprobe sind nicht vorgegeben. Bei ChatGPT/Copilot/Claude ist „Inhalt 0–6“ oder holistische Prozentnoten kaum diskriminierend: Textglätte und Formalia erzeugt das Modell zuverlässig.

8.1 Was bleibt prüfbar (ohne Datei-Upload)

Das Datenmodell erlaubt nur Name, Gewicht, Skala, Beschreibung, eine Zahl. Valide sind Kriterien, die der Prüfer am Abgabeprodukt oder in einer Sitzung stichproben kann:

  • TL2 → Nachvollziehbarkeit (METH, QUEL, REPR, optional IND)
  • Optional TL3 Kolloquium (Gew. 0,5) – sonst Workflow-Blockade

8.3 App-Erweiterungen (später)

  • Vorlagen-Katalog statt leerer StA-Liste / Seed „Inhalt“ (defaultStaCriteria(), defaultPortfolioComponents).
  • Pflicht-description mit operationalisierten Stufen.
  • Kommentar je Kriterium in der Matrix (heute nur Override-Kommentar).
  • Warnung, wenn alle Kriterien nur Form/Inhalt/Sprache sind.
  • Optional Metadaten oral / process / artifact (ändern die Formel nicht).
  • Handbuch §10: KI erlaubt, Bewertung nicht auf Stil; Quellenstichprobe Pflicht; Code ausführen.

9. Sicherheit

Passend zum dokumentierten Bedrohungsmodell. Kein klassisches XSS über Kommentare/Excel nachgewiesen (React-Text, jsPDF-Text).

IndexedDB bleibt unverschlüsselt – XSS, Erweiterung oder geteiltes Profil = Vollzugriff. Das ist Architektur, kein Implementierungsbug.

10. Was bereits gut sitzt

  • Kein Default-Passwort; Production-Build ohne Env bricht ab.
  • Keine App-API, keine Noten auf dem Server.
  • Import-Limits, Dateinamen-Sanitizing, Downloads mit Teams-Fallback.
  • Import-Konflikt mit Diff, Replace nur mit Checkbox.
  • Orphans mit Merge/Dismiss/Undo; No-Show schließt StA/Portfolio-Zellen aus der Export-Validierung aus.
  • Mehrere HIS-Quellen, getrennte Export-Buttons.
  • Szenario-Vergleich, Grenzfall-Markierung, Leistungs-PDF mit Abschnittswahl.
  • 44 Konstellations-Tests; calculateGrade ohne Excel-ROUNDUP, mit ε gegen Float.
  • Echte Kriterienpunkte in Anzeige/PDF-Header (nicht 19,6 von 100 bei Max 66).

11. Umsetzungs-Roadmap

Welle 1 – Daten- und Notensicherheit (1–2 Iterationen)

  1. Auto-Save-Flush + Writer-Queue + BroadcastChannel
  2. clearData inkl. hisSources
  3. StA-Note-Pfad, Portfolio-TL-Mittel, 4,5-Regel
  4. Matrikel-Normalisierung und Moodle-Spaltenpriorität
  5. HIS-Export: Zeilen-Check + gerundete Note

Welle 2 – Export und Workflow-Wahrheit

  1. Validierung auf der Dokumente-Seite
  2. Workflow: kein 100 % ohne Export-OK; THE-Schrittordnung
  3. Punkte-Reimport mergen; Backup nur nach Download-OK
  4. ZIP-Expand-Limits; ZIP-Dateinamen mit ID

Welle 3 – Nutzung und Kriterien

  1. Typgerechte Übersicht, Restliste in der Matrix, Mobile-Sheet
  2. Default-Kriterienkatalog (KI-tauglich) + Handbuch §10
  3. Statistik deduplizieren; Szenarien-Nav nur wenn wirksam
  4. Regressionstests für Header-Varianten, 3513589,0, Zwei-Tab-Save, Folgesemester-Klon
